## Historical purpose

This document previously tracked a complete integrated platform spanning:

- product workspace and application foundation;
- deterministic evolution kernel;
- repository and product understanding;
- internal, public and user research;
- coding-agent execution and sandboxing;
- independent verification and provenance;
- release, deployment and rollback;
- product outcome measurement;
- learning, skill promotion and retirement;
- GitHub, MCP, A2A, self-hosted and hosted operation.

The detailed version remains available in Git history and closed issue #9.

## Why it is frozen

The repository implemented many technically credible parts of this plan before proving that the combined system improved real software delivery for its owner.

The platform roadmap is therefore no longer active. Technical completeness, symmetry between modules, or an unfinished checkbox is not sufficient reason to continue a workstream.

## Reusable technical foundation

The following implemented areas remain available to the practical experiment:

- repository inspection and assessment;
- bounded research and execution handoff records;
- isolated Git worktrees;
- generic command and Codex CLI delivery profiles;
- changed-file scope enforcement;
- separate implementer and verifier identities;
- project-defined checks;
- verified local commits and opt-in draft pull-request publication;
- technical CI and hostile-check fixtures.

They should be treated as internal implementation options, not independent roadmap commitments.

## Re-entry gate

A historical workstream may resume only when:

1. at least two real task records expose the same material problem;
2. the problem cannot be solved adequately through the existing coding agent, Git and project CI;
3. the proposed capability is the smallest reversible experiment;
4. success and removal criteria are defined before implementation.

Until then, all former platform workstreams remain frozen.
